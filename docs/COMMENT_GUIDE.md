# コメント規約 (coverage)

AI・第三者が文脈なしで読めることを目的とする。対象は `coverage/*.py`、`launch/*.py`、`test/*.py`、`DESIGN.md`、`README.md`。

## 1. timeless原則

- コード内コメントに来歴・議論の経緯を書かない（例：「旧〜」「現行」「当面」）。
- 来歴はコミット文・PRに書く。コードには現在の仕様だけ残す。
- 数値の根拠は式・単位で書く。人名・日付・バージョンを書かない（派生ファイルの日付管理は除く）。

## 2. Pythonのdocstring

- モジュールと公開クラス・関数には、責務または入出力の契約をdocstringで書く。
- `coverage_bridge.py` では、topic・action・状態遷移の責務を明記する。
- ROSメッセージ依存のない値変換・検証は、入力と例外条件を明記する。

```python
"""清掃ゾーン点列を検証し、Nav2へ渡せる形に正規化する。"""
```

## 3. 通常コメント

- 書くのは意図・単位・契約の3点：なぜこうするか、単位、前提条件。
- 物理量・周期・QoSには必ず単位・値を付ける（例：`[m]`、`1.0s`、`depth 10`）。
- launchの条件分岐には「いつ有効か」を1行で書く。
- 非同期コールバックには、世代番号・ロック・再試行のような競合回避の意図を書く。

## 4. 禁止事項

- コメントアウトされたコードの放置（不要なら削除し、復元はgitに任せる）。
- 自明な内容の繰返し（コードの朗読）。
- 対話・チャットの文脈を前提にした表現（例：「さっきの」「あの問題」）。

## 5. API文書の生成

Doxygenは未導入である。導入するまでは、READMEのtopic表とDESIGNのインターフェース記述を利用者向け文書の正本とする。
